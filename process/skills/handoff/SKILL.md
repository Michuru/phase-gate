# Handoff: brief a fresh context window

This is **not** `end-task` (session close: commit, docs-sync, done, if you have that skill installed) and not the harness's automatic compaction. It continues the *same* in-progress task under a fresh budget.

## Direction: outgoing (write a primer) or incoming (resume from one)

- `/handoff resume` or `/handoff continue` → incoming.
- Bare `/handoff` after substantial prior conversation (multi-turn work in progress) → outgoing.
- Bare `/handoff` at or near the start of a fresh session → likely incoming.
- Genuinely ambiguous either way → ask.

**Incoming:** run `python "${CLAUDE_SKILL_DIR}/scripts/handoff_scan.py"` (it lists the live primers), then read `${CLAUDE_SKILL_DIR}/references/incoming.md` now and follow it. The outgoing steps below do not apply. If the conversation is compacted while you are inside that branch, re-read the reference before continuing. **Note the primer's path if this session's own work starts from a resume**: Outgoing step 5 consumes it.

## Outgoing

1. **Check whether the harness already compacted this session, before assembling anything.** If it did, say so, and say in the primer that it was assembled from a post-compaction summary: the early decisions the primer most needs may be gone. A primer that passes a summary off as "here's what we decided" is worse than none.
2. **Assemble from the conversation directly**: goal, key decisions already made, the exact design doc, `BACKLOG.md` entry or file and lines to point the fresh session at, go-ahead points still open, caution flags (worktree versus main checkout, a peer touching the same file). Do not re-explore the repo to rebuild any of it. Keep it lean: a fresh session already starts with a large fixed floor, so prefer pointers (a section name, a path with line range, a commit hash) to pasted text, and paste only what exists nowhere on disk. Also run `git status --short` in every repo touched this session and fold the raw output in as-is: report only, never stage, commit or judge, so the fresh session is not surprised by uncommitted state.
3. **Path:** `<repo-root>/.claude/handoffs/<YYYY-MM-DD>-<slug>.md`, where `<repo-root>` is the repo the work is happening in (by cwd, never hardcoded to any one repo; an external repo counts) and `<slug>` is short kebab-case. **Never overwrite**: if the path exists, append `-<HHMM>` (step 5 consumes the *source* primer after this one is written, so reusing its name would overwrite the live file and then archive it). The folder holds user-facing primers only.
4. **Write the file** to that path.
5. **Consume the source primer, then tell the user.** If this session's own work began from a resume, consume that primer now, before anything else in this step, with the script: `python "${CLAUDE_SKILL_DIR}/scripts/handoff_consume.py" "<source primer path>" --reason "superseded by <new primer path>" --trailer "<a trailer line>"`, repeating `--trailer` once per trailer line your setup asks commits to carry (for example a `Co-Authored-By` line; omit the flag if there are none). Exit 0: consumed, and the marker was proven in `git show HEAD:`. Exit 1: refused or rolled back, the primer is as it was; tell the user why. Exit 2: the commit landed but the proof failed; tell the user, do not report it consumed, a corrective commit is needed. **The script is the only way to consume a primer**: never hand-roll the marker or the `git mv` (that failed repeatedly, and `Read`ing the file back does not prove what was committed). A brand-new thread has no predecessor to consume. Then give the user the primer's full path and a one-line summary of what it continues. Do not print its contents.
5b. **Open-items check, before the "safe to clear" line (and before step 6, so its commit carries any `BACKLOG.md` change).** Every open item the session knows of (work found and not done, anything waiting on the owner, a residual a QA pass named, a deferred step, a promised next) must be a discrete `BACKLOG.md` line; check by grep, not memory. A bullet's "Next:" prose or the primer's own list does not count: `/backlog` cannot list, rank or snooze prose. Add the missing ones with the `backlog` skill's quick capture (only your own hunks; if `BACKLOG.md` shows `MM` or carries someone else's hunks, name it in the primer instead of committing it). **If step 6 does not apply in your setup, those lines are still uncommitted: commit them narrowly yourself, or name the file in the step 7 report as left uncommitted.** The primer's open-items section then only **points** at those lines (their names or a grep), never the only record. Step 7's confirmation states the result: `open items: N, all on BACKLOG.md (<short names>)` or `no open items`. A session once said it was safe to clear with five open items that existed only in one bullet and a primer.
6. **Make a narrow WIP commit so the primer has backup coverage, if your setup needs it.** If your setup has a mechanism that bundles only committed history (for example a `SessionEnd` hook feeding an external backup tool), a new primer (and the design doc, notes or `BACKLOG.md` edit it points at) has none until committed; if it has no such mechanism, this step is optional. Right after writing the primer, stage narrowly the primer plus whatever specific uncommitted files it points at, never `-A` or `.`; if they live in different repos, commit narrowly in each. **Before committing a path that already existed, run `git status --short` on it: `MM`, or staged by another session, means it is not yours to commit** (a pathspec commit takes the working-tree content and would sweep in a peer's half-staged hunks); name it in the primer instead. Stage a brand-new file with `git add <file>` first. Start the message with `WIP checkpoint:` and say plainly what is not finished and that the commit exists only for backup coverage. This is a standing exception scoped to this skill, never a signal the work is done.
7. **Confirm and stop.** Say the handoff is written (and committed, if step 6 applied), in the same message give step 5b's open-items line and say it is safe to `/clear` now (one line is enough), and chain nothing else: no docs-sync, no archive move, no cheat-sheet refresh (those belong to `end-task`, if you have it). Next command, if your setup uses a next-command contract: **`/clear`**; the named alternative is carrying on in this session if there is more to do first.
