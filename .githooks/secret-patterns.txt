# Secret-shape patterns for .githooks/scan-secrets.sh - one ERE (grep -E) per
# non-comment, non-blank line.
#
# THIS FILE SHIPS EMPTY ON PURPOSE. The scanner runs, finds no patterns to
# match, and reports nothing until you add your own. That is the intended
# starting state: a pattern you did not write is a pattern you will not trust,
# and a false positive on day one teaches you to reach for --no-verify, which
# is the exact habit this guard exists to prevent.
#
# ---------------------------------------------------------------------------
# HOW TO WRITE A GOOD PATTERN
# ---------------------------------------------------------------------------
#
# Track the SHAPE of a specific, real credential form - ideally one you have
# actually leaked before, since that is the one you will leak again. Do NOT
# write a generic `token=...` or `password=...` pattern. In any repo whose own
# documentation discusses credentials by name (a design doc explaining a token,
# a mistakes log recording a leak, a README telling users where to put theirs),
# a generic pattern fires constantly on prose that contains no secret at all.
# A guard that cries wolf is a guard that gets bypassed.
#
# A good pattern is specific enough that a genuine placeholder reference -
# {token}, <token>, $TOKEN, an f-string {token} - cannot match it. The usual
# trick is to require an actual alphanumeric value immediately after the
# delimiter, so a brace or angle bracket fails the match.
#
# Also note: values matching Claude Code's own redaction placeholders
# (__TRACKED_VAR__, __CMDSUB_OUTPUT__) are excluded by the scanner itself, so
# you do not need to special-case them here.
#
# ---------------------------------------------------------------------------
# WORKED EXAMPLE - commented out; uncomment and adapt, or delete
# ---------------------------------------------------------------------------
#
# A service token passed as an HTTP header value or a URL query-string
# literal, e.g. `-H 'X-Some-Service-Token: <value>'` or
# `?X-Some-Service-Token=<value>`. The character class after the delimiter
# requires a real value, so `{token}` / `<token>` / `$TOKEN` never match:
#
#   X-Some-Service-Token[:=][ ]*['"]?[A-Za-z0-9_]{15,25}
#
# The same credential built via printf rather than passed as a single
# recognizable argument - worth a second pattern, because a value written to a
# file by a shell command looks nothing like the header form above:
#
#   printf ['"]%s['"][^"']*['"][A-Za-z0-9_]{15,25}['"]
#
